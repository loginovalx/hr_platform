# Кадры · Горький

Платформа муниципального подбора для хакатона. В одном приложении работают карьерная витрина, гостевые отклики, кабинет HR и анкеты обратной связи.

Решения команды, замечания и состояние развёртывания собраны в [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md).

## Запуск демо

Требуется Node.js 24 или новее.

```sh
npm run dev
```

Откройте http://127.0.0.1:3000/hr и нажмите "Открыть демо-кабинет" для роли руководителя или "Демо кадровика" для роли специалиста. Кабинет подразделения открывается по адресу http://127.0.0.1:3000/department. В локальном демо его логин для передачи карточки - `department`.

Учебная база содержит четыре вакансии, включая консультанта сектора подбора, однофамильцев, пример переподготовки, отказ, найм и анкету после увольнения. При запуске поверх прежней учебной базы с тремя вакансиями добавляются консультант и учебный отклик. Повторный запуск сохраняет существующие записи.

```sh
npm test
```

Для сквозной проверки интерфейса установите Playwright в рабочее окружение и соберите приложение.

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run build
node scripts/check-ui.cjs
```

Проверка запускает отдельную учебную базу и headless Chromium. Она проверяет экраны при ширинах 320, 390, 768, 1024 и 1440 пикселей, приём DOCX и TXT, статус гостевого отклика, обработку заявки подразделения, интервью, передачу карточки и печать справки. Путь к снимкам и PDF выводится в конце. Можно передать каталог в первом аргументе. Для уже установленного браузера и пакета предусмотрены `CHROMIUM_EXECUTABLE` и `PLAYWRIGHT_PACKAGE`.

## Самостоятельное размещение

```sh
npm run build
SEED_DEMO=0 HOST=0.0.0.0 PUBLIC_ORIGIN=https://your-host.example npm start
```

Перед запуском передайте через окружение `ADMIN_PASSWORD` для роли `admin` и при необходимости `HR_PASSWORD` для роли `hr`. Роль администратора открывает оформление увольнений и ответы на анкеты бывших сотрудников. `PUBLIC_ORIGIN` задаёт канонический адрес за HTTPS-прокси. `DATA_DIR` указывает каталог SQLite и вложений. `SEED_DEMO=0` отключает учебное наполнение и его обновления. `DEPARTMENT_PASSWORD` включает отдельный вход под логином `department` для кабинета подразделения.

В самохостинге гостевые вакансии и анкеты доступны по прямым ссылкам. В варианте Sites данные хранятся в D1, вложения в R2. Для служебного доступа на Sites задайте `OWNER_ID` или `STAFF_ACCESS_JSON`. Указывайте идентификаторы, которые хостинг передаёт в доверенном заголовке `oai-authenticated-user-id`. Аккаунты без назначения имеют доступ к гостевым маршрутам в рамках настроек видимости сайта.

```json
{
  "manager-account": {"role":"admin"},
  "recruiter-account": {"role":"hr","vacancyIds":["vacancy_4"]},
  "department-account": {"role":"department"}
}
```

Хостинговый `hr` видит карточки, резюме и показатели назначенных вакансий. Кадровик может готовить версии назначенных вакансий. Создание вакансий, согласование чужих версий и доступ к общему архиву доступны администратору. Представитель подразделения видит карточки, переданные на его ID. Перед публикацией на Sites проверьте назначения по фактическим аккаунтам организаторов.

### Учебный стенд на Amvera

1. Создайте приложение в российском регионе Amvera. Загрузите исходники с `amvera.yml` и `.openai/hosting.json` из корня репозитория. Конфигурация собирает приложение на Node 24, запускает одну копию на порту 3000 и хранит SQLite с вложениями в `/data`. [Быстрый старт](https://docs.amvera.ru/applications/quick-start.html) · [Постоянное хранилище](https://docs.amvera.ru/applications/storage.html)
2. В разделе "Домены" включите бесплатный HTTPS-домен Amvera. Укажите выданный HTTPS-адрес без завершающего слеша в `PUBLIC_ORIGIN`. Посетителям витрины не нужна учётная запись Amvera. [Настройка домена](https://docs.amvera.ru/applications/configuration/network.html)
3. В конфигурации стенда укажите `SEED_DEMO=1`, `SYNTHETIC_ONLY=1` и `DEMO_MODE=0`. Задайте `ADMIN_PASSWORD` и при необходимости `HR_PASSWORD`, `DEPARTMENT_PASSWORD` через секреты проекта. Гостевая форма принимает учебные адреса. Кабинет кадровика остаётся под паролем. [Переменные и секреты](https://docs.amvera.ru/applications/configuration/variables.html)
4. На выданном домене проверьте `/health` с версией приложения, `/vacancies` с учебной вакансией консультанта, затем войдите в `/hr/feedback` и откройте вкладку "Вопросы для интервью" в карточке учебного отклика.

Для одного учебного стенда подходит тариф "Начальный" с 500 МБ памяти. На 20 ноября 2026 года он указан по цене 290 ₽ за 30 дней. [Тарифы Amvera](https://docs.amvera.ru/general/price.html)

## Приём и разбор

- Форматы вложений: TXT, DOCX и PDF до 5 МБ. TXT и DOCX разбираются в приложении. В самохостинге для извлечения текста из PDF используется `pdftotext` (Poppler), если он доступен. Для PDF на демохостинге и сканов можно приложить оригинал и вставить текст вручную.
- В "Откликах" можно добавить запись вручную, загрузить EML с одним поддерживаемым вложением или принять пакет JSON до 20 поступлений. `sourceChannel`, `sourceAccount` и `deliveryId` определяют доставку. Пакет без ID использует отпечаток исходных полей строки. Изменённая запись с прежним ID возвращается на сверку. В EML используется `Message-ID`, а при его отсутствии - отпечаток письма.
- Через "Импортировать" можно также загрузить до 20 резюме DOCX или TXT. Сверьте фамилии и имена перед приёмом. Каждая строка получает собственный результат. Повтор одного файла для той же вакансии и соискателя не создаёт второй отклик.
- В профиле кандидата "Добавить документ" предзаполняет события из файла с разделом "История общения с кандидатом" или "История", включая формат документа № 154. Для вставленного текста используйте "Найти события в документе". Сверьте даты, должности и фрагменты, затем сохраните. Повтор того же проверенного файла сохраняет одну историю. Если этот источник уже сохранили без событий, они добавятся к документу. Архив не входит в текущую воронку.
- Разбор сохраняет фрагменты источников. Для требований к стажу и составных условий показывает, что уточнить. В учебной вакансии консультанта справка показывает оба пути из п. 2.2.1 и разделяет переподготовку и повышение квалификации. Цитата открывается в контексте исходного текста. Вкладку "Справка" можно распечатать или сохранить в PDF. Вывод и основание правки кадровика хранятся в истории.
- "Вакансии", "Отклики" и "Кандидаты" видны сразу. "Обзор", "Аналитика", "Обратная связь" и публичные вакансии открываются через "Дополнительно".
- По фамилии находятся профили и свежие непривязанные отклики. Однофамильцев связывает кадровик. Фильтры реестра учитывают основное и дополнительное образование, опыт и связанные резюме. В очереди можно сохранить фильтры, а в реестре кандидатов - выбрать колонки для текущего браузера.
- Подразделение создаёт и подтверждает заявку. Кадровик подготавливает вакансию из этой заявки. После публикации в заявке появляется ссылка на вакансию.
- Во "Взаимодействии" доступны телефонные и очные интервью, отдельный разбор по другой вакансии и передача карточки ответственному. Перед отправкой видно, какие сведения получит подразделение. Его решение и обоснование отображаются в карточке, а очередь фильтруется по наличию ответа.
- По ссылке из квитанции соискатель видит состояние отклика. При итоговом решении кадровик может отдельно написать ему рекомендацию. Внутренняя причина отказа остаётся в кабинете кадровика.
- При добровольном уходе и при увольнении по инициативе работодателя используются разные анкеты. Аналитика администратора показывает причины добровольного ухода и агрегаты по увольнениям. Персональные ссылки на анкеты и уточнения кадровик отправляет вручную.
- Правки опубликованной вакансии проходят черновик, отправку, согласование другим руководителем и публикацию. Кадровик готовит черновик, руководитель согласует или возвращает с причиной. Версия и участники сохраняются.

### Очередь первичного разбора

В "Откликах" фильтр "Очередь разбора" показывает число записей по каждому статусу с учётом вакансии, этапа, источника и поиска. Фильтр применяется ко всей выборке до пагинации. Статус и причина также видны в карточке отклика.

- **Рассмотреть в первую очередь** - по каждому обязательному требованию есть цитата с совпадением или подтверждение HR.
- **Нужно уточнение** - отсутствует основание по части требований или есть пропуски в обязательных вопросах теста.
- **Проверить данные** - отсутствует источник, читаемый текст или рабочий контакт. Архивные записи без контакта остаются доступны для разбора.
- **Расхождение подтверждено HR** - кадровик уже сверил обязательное требование и зафиксировал несоответствие.
- **Ручной разбор**, **идёт разбор** и **завершён** отражают состояние обработки, наличие обязательных критериев и итог подбора.

Расчёт использует локальный разбор, закреплённую версию критериев и правки кадровика. Он обновляется после уточнений и не вызывает модель. Отказ, перевод этапа и наём остаются действиями кадровика.

## Черновик вопросов для интервью

В карточке отклика откройте "Вопросы для интервью". Локальный план ставит первыми обязательные требования с пробелами, затем дополнительные пробелы и вопросы для проверки приведённых примеров. Кадровик может выбрать вопросы, поправить их и скопировать список. Через "Записать ответ" сохраняются слова кандидата, вопрос, автор, время и следующий шаг. Отдельный источник доступен в разборе, а исходное резюме сохраняется.

Для обсуждения смежных ролей приложение берёт факты из резюме и ответов на уточнения. Оно сравнивает до 40 доступных опубликованных вакансий, показывает до трёх вариантов по покрытиям требований и указывает фрагменты и вопросы. "Сохранить проверку" добавляет её в историю во вкладке "Взаимодействие". Вакансию и итог отклика определяет кадровик.

Кнопка "Уточнить формулировки с ИИ" обращается к настроенной модели за двумя наиболее приоритетными формулировками. В запросе только временные номера критериев, категории требований, состояния проверки и типы источников. Резюме, цитаты, имена, контакты, формулировки требований и комментарии остаются внутри платформы. Повтор одинаковых обезличенных входных сведений использует кеш до десяти минут. При ошибке модели остаются локальные вопросы и правки кадровика.

Для GigaChat задайте серверный секрет `GIGACHAT_AUTH_KEY`. Область `GIGACHAT_SCOPE` по умолчанию равна `GIGACHAT_API_B2B`, модель задаётся через `GIGACHAT_MODEL` (по умолчанию `GigaChat`). Запрос идёт на `api.giga.chat`. Для старого подключения можно явно выбрать прежний адрес через `GIGACHAT_LEGACY_API=1`. Для Node.js при необходимости настройте доверенный сертификат через `NODE_EXTRA_CA_CERTS`. [Авторизация GigaChat API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api)

Если GigaChat не настроен, можно использовать `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Для сервисного аккаунта проверьте роль `ai.languageModels.user` на каталоге и область действия ключа `yc.ai.foundationModels.execute`. `YANDEX_MODEL` по умолчанию равен `yandexgpt-lite`. [Документация Yandex Cloud](https://yandex.cloud/ru/docs/iam/concepts/authorization/api-key)

## Аналитика рабочей нагрузки

- Период и вакансия ограничивают выборку по дате поступления отклика. Исторические документы исключены. Медиана считается от регистрации до первого записанного действия по этапу. Рядом видно, сколько откликов вошло в расчёт. Ноль замеров отображается отдельно.
- Открытые отклики без действий и карточки, ожидающие ответа подразделения, ведут в соответствующие очереди. Просрочка считается по сроку ответа на текущий момент. Источники сравниваются по числу поступлений и числу откликов без действий.
- По кнопке GigaChat может упорядочить до двух приоритетов. В запросе только числовые агрегаты и разрешённые коды действий. Значения, выводы и ссылки берутся из локального расчёта. Запрос ограничен 160 токенами, одинаковые входы используют кеш до десяти минут. При отсутствии ответа работают локальные приоритеты.
- Скорость первичной обработки и экономию времени кадровика измеряют отдельно. Для пилота сравните медиану времени и количество ошибок на одинаковых учебных задачах с ручным переносом и с предзаполнением.

## Контракты

`openapi.yaml` описывает публичный API и кабинет HR. Примеры запросов, ответов и событий находятся в `examples/`.

Сохранение заявки, связанных ответов и события приёма выполняется транзакцией. Обработка события идемпотентна. Сервер защищает версии этапов и однократные ответы, а повтор запроса с тем же `Idempotency-Key` возвращает сохранённый результат.

## Границы демонстрации и пилота

Форма на демохостинге и в режиме демо просит подтвердить использование вымышленных данных и принимает адреса в доменах `.test` и `.example`. Это правило демонстрации. Для работы с реальными данными администрация определяет контур размещения, основания и сроки обработки, порядок запросов на удаление, учётные записи и аудит доступа.

Для пилота заказчик определяет правила штатного и нештатного подбора и доступ к муниципальному кадровому резерву. Прямые подключения к рабочей почте и hh.ru требуют отдельных учётных записей и согласования с заказчиком. Защита использует учебные данные. Прогон архивного сценария № 154 использует учебный аналог с тремя событиями по двум должностям. Замер экономии времени кадровиков требует сравнения на сопоставимых учебных заданиях.
