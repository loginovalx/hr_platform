# Кадры · Горький

Платформа муниципального подбора для хакатона. В одном приложении работают карьерная витрина, гостевые отклики, кабинет HR и анкеты обратной связи.

## Запуск демо

Требуется Node.js 24 или новее.

```sh
npm run dev
```

Откройте http://127.0.0.1:3000/hr и нажмите "Открыть демо-кабинет". Новая база содержит четыре учебные вакансии, включая консультанта сектора подбора, двух однофамильцев, пример переподготовки, архивный импорт, отказ, найм и анкету после увольнения. Новые данные сохраняются после перезапуска.

```sh
npm test
```

## Самостоятельное размещение

```sh
npm run build
SEED_DEMO=0 HOST=0.0.0.0 PUBLIC_ORIGIN=https://your-host.example npm start
```

Перед запуском передайте через окружение `ADMIN_PASSWORD` для роли `admin` и при необходимости `HR_PASSWORD` для роли `hr`. Роль администратора открывает оформление увольнений и ответы на анкеты бывших сотрудников. `PUBLIC_ORIGIN` задаёт канонический адрес за HTTPS-прокси. `DATA_DIR` указывает каталог SQLite и вложений. `SEED_DEMO=0` применяется при инициализации новой базы.

В самохостинге гостевые вакансии и анкеты доступны по прямым ссылкам. В форме отклика можно прикрепить один файл или написать резюме текстом. Ответы на тесты прошлых откликов доступны в их карточках. При поступлении отклика автоматически создаётся профиль кандидата. Опубликованное демо использует закрытый доступ по аккаунту и синтетические данные. Хостинговый вариант хранит записи в D1, а вложения в R2.

## Приём и разбор

- Форматы вложений: TXT, DOCX и PDF до 5 МБ. TXT и DOCX разбираются в приложении. В самохостинге для извлечения текста из PDF используется `pdftotext` (Poppler), если он доступен. Для PDF на демохостинге и сканов можно приложить оригинал и вставить текст вручную.
- Почтовые отклики вводятся вручную. Архив принимает JSON до 20 записей за запрос. Пример доступен в диалоге импорта, а отчёт показывает ошибки по строкам.
- Обработчик ищет цитаты локально. Автоматический разбор образования отправляет найденное основание на ручную сверку. Правка HR с обоснованием хранится отдельно. Поле "Основание или пункт инструкции" сохраняется в опубликованной версии вакансии.
- "Вакансии", "Отклики" и "Кандидаты" видны сразу. "Обзор", "Аналитика", "Обратная связь" и публичные вакансии открываются через "Дополнительно".
- В реестре доступны поиски по дополнительному образованию и по словам из опыта и связанных резюме. Для одной вакансии опция "По приоритету проверки" сортирует все отклики по подтверждениям HR и найденным цитатам. В аналитике администратора есть разбивка увольнений по подразделению, месяцу и основанию.
- Для анкет и уточнений приложение готовит персональные ссылки. HR отправляет их вручную и отмечает отправку анкеты в кабинете.

### Очередь первичного разбора

В "Откликах" фильтр "Очередь разбора" показывает число записей по каждому статусу с учётом вакансии, этапа, источника и поиска. Фильтр применяется ко всей выборке до пагинации. Статус и причина также видны в карточке отклика.

- **Рассмотреть в первую очередь** - по каждому обязательному требованию есть цитата с совпадением или подтверждение HR.
- **Нужно уточнение** - отсутствует основание по части требований.
- **Проверить данные** - отсутствует источник, читаемый текст или рабочий контакт. Архивные записи без контакта остаются доступны для разбора.
- **Расхождение подтверждено HR** - кадровик уже сверил обязательное требование и зафиксировал несоответствие.
- **Ручной разбор**, **идёт разбор** и **завершён** отражают состояние обработки, наличие обязательных критериев и итог подбора.

Расчёт использует локальный разбор, закреплённую версию критериев и правки кадровика. Он обновляется после уточнений и не вызывает модель. Отказ, перевод этапа и наём остаются действиями кадровика.

## Черновик вопросов для интервью

В карточке отклика откройте "Разбор" и нажмите "Вопросы для интервью". Модель получает только временные номера критериев, категории требований, состояния проверки и типы источников. Резюме, цитаты, имена, контакты, формулировки требований и комментарии остаются внутри платформы. Ответы с распространёнными личными темами отбрасываются. HR проверяет оставшийся черновик перед интервью. При отсутствии настроек или ошибке API приложение показывает вопросы из опубликованной версии вакансии.

Для GigaChat задайте серверный секрет `GIGACHAT_AUTH_KEY`. Область `GIGACHAT_SCOPE` по умолчанию равна `GIGACHAT_API_B2B`, модель задаётся через `GIGACHAT_MODEL` (по умолчанию `GigaChat`). GigaChat используется по кнопке кадровика, максимум два критерия и 160 выходных токенов за запрос. Повтор набора критериев в течение десяти минут в том же серверном процессе использует кеш. Для Node.js при необходимости настройте доверенный сертификат через `NODE_EXTRA_CA_CERTS`. [Документация GigaChat API](https://developers.sber.ru/docs/ru/gigachat/legal-quickstart)

Если GigaChat не настроен, можно использовать `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Для сервисного аккаунта проверьте роль `ai.languageModels.user` на каталоге и область действия ключа `yc.ai.foundationModels.execute`. `YANDEX_MODEL` по умолчанию равен `yandexgpt-lite`. [Документация Yandex Cloud](https://yandex.cloud/ru/docs/iam/concepts/authorization/api-key)

## Контракты

`openapi.yaml` описывает публичный API и кабинет HR. Примеры запросов, ответов и событий находятся в `examples/`.

Сохранение заявки, связанных ответов и события приёма выполняется транзакцией. Обработка события идемпотентна. Сервер защищает версии этапов и однократные ответы, а повтор запроса с тем же `Idempotency-Key` возвращает сохранённый результат.

## Границы демонстрации и пилота

Форма на демохостинге и в режиме демо предлагает использовать вымышленные данные и принимает адреса в доменах `.test` и `.example`. Это правило демонстрации. Для работы с реальными данными администрация определяет контур размещения, основания и сроки обработки, порядок запросов на удаление, учётные записи и аудит доступа.

Отдельный кабинет подразделения с заявкой и обратной связью, муниципальный кадровый резерв и разбор трёх архивных событий из контрольного файла № 154 относятся к следующей итерации этой реализации. Замер экономии времени проводится на одинаковых учебных заданиях для ручного процесса и платформы.
