# Кадры · Горький | Передача работы

На 20 ноября 2026 года рабочий репозиторий команды - `loginovalx/hr_platform`. Этот файл относится к ветке `codex/hr-yandexgpt`. Корневая папка `gorky` содержит также материалы кейса и прежний прототип `kadrovy-marshrut/app`. Единая карточка и демонстрация команды находятся в этом репозитории.

## Задача со встречи 20 ноября

- Пользователь попросил проверить, соответствует ли ссылка на обратную связь текущей сборке, и найти публичный HTTPS-адрес без `chatgpt.site`. Российский хостинг предпочтителен.
- По сценарию Чаркина кандидат может заполнить резюме неполно и податься на одну должность, хотя его опыт пригодится на другой. Кадровику нужна отдельная вкладка с готовыми вопросами по пробелам и вариантами смежных вакансий для обсуждения.
- Сначала работает локальный алгоритм. Модель предлагается для точечной правки формулировок по запросу кадровика. Подготовка интервью не меняет оценку, этап или привязку отклика.
- Команда ведёт общий журнал в этом файле. При передаче работы нужны факты об изменениях, проверки и открытые вопросы с источником замечания.

## Приёмка вкладки интервью

1. В карточке отклика открывается вкладка вопросов. Она работает без ключей модели и показывает выше вопросы по обязательным требованиям с пробелами.
2. Предложения по смежным вакансиям опираются на профессиональный фрагмент резюме или ответа на уточнение. У каждой роли видны основание и вопрос, который стоит задать. Порядок ролей определяется наличием оснований по требованиям вакансии. Кадровик решает, продолжать ли проверку.
3. Вопросы можно выбрать, отредактировать и скопировать. Модель по кнопке переформулирует до двух вопросов. ФИО, контакты, цитаты и тексты заявок остаются в приложении.
4. Код доступа кадровика ограничивает подбор доступными вакансиями. Гостевой доступ к карточке вопросов закрыт.
5. HTTPS-адрес проверяется по маршрутам `/health`, `/vacancies` и `/hr/feedback`. Передача доступа для жюри проводится отдельно от развёртывания кода.

## Как вносить изменения

- Перед началом прочитайте `git status --short --branch`, журнал ниже и последние коммиты по вашим файлам. В общей папке чужой незакоммиченный diff может быть актуальной работой. Сверьте назначение изменений перед правкой пересекающихся файлов.
- Занимайте конкретный участок и оставляйте короткую запись перед передачей. Для альтернативных ролей используйте существующий `related-reviews`, для подтверждений - закреплённые критерии и оценку кадровика. Схему API поддерживайте в `openapi.yaml`.
- Замечание другого участника записывайте с датой, источником и проверяемым результатом. При противоречии фиксируйте обе формулировки и наблюдаемое поведение, пока команда не согласует одну. В журнале отличайте учебную проверку от проверки опубликованной версии.

## Где продолжать работу

- `npm test` проверяет в том числе 420 уникальных откликов, повтор пакета, три архивных события № 154 по двум должностям, поиск фактов из архива, оба пути образования, ответы со слов кандидата, согласованную заявку, статус гостя и получение ответа подразделения.

- Роли для реального ведомства, официальный импорт из hh.ru и рабочих ящиков, отдельные процедуры штатного и нештатного подбора и расширенный конструктор требуют согласования правил заказчика. Для измерения эффекта нужен сравнительный прогон с людьми. Демонстрация использует синтетические данные.

Рабочие сведения о запуске, ролях и форматах импорта есть в [README.md](README.md). После успешного развёртывания внесите сюда выданный URL, версию с `/health` и результат входа в кабинет с другого компьютера.
